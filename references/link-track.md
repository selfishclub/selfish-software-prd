# 링크로 여는 소프트웨어 (모양 ② · ③)

인터넷에 올려서 링크로 여는 소프트웨어를 만들어요.
- **②**: 로그인 없이, 데이터는 그 기기의 **브라우저 안에** 저장해요.
- **③**: ②와 똑같이 만들다가, 5단계에서 가벼운 로그인과 DB를 붙여요. 표시된 곳에서 `light-login.md`를 함께 읽어요.

사용자에게 처음 한 번 설명해요.
- ②: "인터넷에 올라가서 링크로 열려요. 기록은 지금 쓰는 기기의 브라우저 안에 저장돼서, 로그인이 없어도 다른 사람은 내 기록을 볼 수 없어요."
- ③: "인터넷에 올라가서 링크로 열리고, 닉네임과 비밀번호로 들어가요. 폰에서 쓰든 노트북에서 쓰든 같은 기록이 보여요."

## 기술 결정 (사용자에게 묻지 않고 정해요)

입문자에게 프레임워크를 고르게 하면 시간만 가요. 아래로 고정하고, 왜 쓰는지만 한 줄씩 알려 줘요.

| 항목 | 선택 | 사용자에게 할 설명 |
|---|---|---|
| 프레임워크 | Next.js (App Router, TypeScript) | 요즘 웹 서비스를 만들 때 가장 많이 쓰는 뼈대예요. 나중에 SaaS로 키우기도 쉬워요 |
| 디자인 | Tailwind CSS | 색, 간격을 짧은 이름으로 바로 입히는 도구예요 |
| 저장 | ② 브라우저 localStorage / ③ Supabase | ②는 브라우저 안의 작은 서랍, ③은 무료 DB예요 |
| 배포 | Vercel Hobby | 개인용은 무료이고 카드 등록도 필요 없어요 |

모두 무료예요. 사용자에게도 "오늘 쓰는 도구는 전부 무료예요"라고 한 번 말해 줘요. 추가 패키지는 꼭 필요할 때만 하나씩 넣고, 넣을 때마다 이름과 이유를 말해요. 패키지가 많을수록 보안 구멍이 생길 곳도 많아져요.

## 폴더 구조

```
<사용자가 연 폴더>/        ← 이름은 한글이어도 돼요
├── PRD.md                설계도
├── WORKLOG.md            작업 기록
└── <영어-이름>/           ← 실제 코드 (create-next-app이 만들어요)
```

코드를 하위 폴더에 두는 이유가 두 가지 있어요.
- create-next-app은 `PRD.md`가 있는 폴더에서 실행되지 않아요.
- npm은 한글 · 대문자 · 띄어쓰기가 들어간 이름을 받지 않아요.

영어 이름은 소프트웨어 이름을 바탕으로 **소문자 · 숫자 · 하이픈**으로 만들어서 객관식으로 확인받아요. 예: "오늘의 딱 3가지" → `today-three` (추천) / `my-today` / 직접 입력

## 4단계 · 화면 먼저

📍 "지금은 기능 없이 생김새만 먼저 만들어요. 집으로 치면 모형부터 보는 거예요."

1. 프로젝트 폴더에서 아래 명령으로 뼈대를 만들어요.
   ```
   npx create-next-app@latest <영어-이름> --ts --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --yes
   ```
   - 이후 명령은 모두 `<영어-이름>` 폴더 안에서 실행해요.
   - 설치 끝에 "취약점 N개, `npm audit fix --force`"가 보일 수 있어요. 대부분 만드는 동안만 쓰는 검사 도구 쪽이에요. `--force`는 쓰지 않아요. 따라 하면 오히려 프로젝트가 깨져요. 6단계에서 인터넷에 올라가는 부분만 따로 확인한다고 미리 말해 줘요.
   - **윈도우**에서 "스크립트를 실행할 수 없으므로…" 오류가 나면 `npx` 대신 `npx.cmd`로 실행해요. 보안 설정을 바꾸지 않아도 돼요.
2. **git을 확인해요.** 커밋은 게임의 세이브 같은 거예요. 망가져도 그 지점으로 돌아올 수 있어요.
   - create-next-app은 보통 git 저장소와 첫 커밋까지 만들어 둬요. `git log --oneline`으로 확인해요.
   - 커밋이 없거나 저장소가 없으면, 대개 이 컴퓨터에 git 이름 · 이메일이 설정되지 않아서 첫 커밋이 안 된 거예요. `git init`(필요하면) → 이 프로젝트에만 이름 · 이메일 설정(`git config user.name "<닉네임>"`, `git config user.email "<닉네임>@users.noreply.github.com"`, `--global` 없이) → 첫 커밋 순서로 해요.
   - 사용자에게 "세이브가 한 번 됐어요"라고 알려 줘요.
3. **기본 설정을 먼저 바꿔요.** 여기서 해 두면 6단계 보안 점검이 "다 통과"로 끝나요.
   - `src/app/layout.tsx`
     - `lang="ko"`
     - `title` · `description`을 소프트웨어 이름으로
     - `robots: { index: false, follow: false }`: 개인용이라 검색에 안 뜨게 해요
   - `next.config.ts`에 보안 헤더를 넣어요 (`security-checklist.md`의 헤더 항목). 이미 들어 있는 설정은 지우지 말고 `headers()`와 `poweredByHeader: false`만 더해요. 파일을 통째로 다시 쓰면 Next.js 기본 설정이 날아가요.
   - 글꼴: 기본 Geist는 영문 전용이에요. 원하는 글꼴이 없으면 Geist를 빼고 시스템 글꼴(`-apple-system, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif`)을 써요. 폰에서 가장 빨리 열려요. 구글 폰트로 한글 글꼴을 쓸 때만 `next/font/google`에 `preload: false`를 넣어요.
   - `AGENTS.md`는 Next.js가 AI 도구용으로 만든 안내 파일이에요. 그대로 두고, 버전마다 달라진 점이 있으면 그 안내대로 `node_modules/next/dist/docs/`를 참고해요.
   - 기본 `README.md`는 8단계에서 이 소프트웨어 설명으로 바꿔요.
4. 폴더 구조를 3줄로만 설명해요.
   - `src/app/page.tsx` 첫 화면
   - `src/components/` 화면 조각들
   - `public/` 그림 파일
5. PRD의 화면 표대로 **가짜 데이터**로 화면을 만들어요. 그럴듯한 예시로 채우되, 실존 인물 이름이나 실제 연락처는 넣지 않아요. ③도 이 단계에서는 로그인 없이 화면만 만들어요.
6. 개발 서버를 켜고(`npm run dev`) 로컬 링크(`http://localhost:3000`)를 열어 보여 줘요. Claude 데스크톱 앱이면 미리보기 창으로 띄워요.
   > "로컬 링크는 내 컴퓨터에서만 열리는 미리보기 주소예요. 앞으로 '미리보기 띄워줘', '로컬 링크 띄워줘'라고 하시면 언제든 다시 열어 드릴게요."
7. 피드백을 객관식으로 받아요: 이대로 좋아요 / 색 · 분위기를 바꾸고 싶어요 / 배치를 바꾸고 싶어요 / 글자 크기를 바꾸고 싶어요. 바꾸고 싶다고 하면 "느낌으로 말씀하셔도 돼요. '좀 답답해', '더 귀엽게'처럼요"라고 덧붙여요. 화면이 마음에 들 때까지 고쳐도 돼요.
8. 폰 너비(375px)에서도 보여 줘요. 로컬 링크는 폰에서 열리지 않아서, 진짜 폰 확인은 배포한 뒤에 해요.
9. 커밋해요.

## 5단계 · 기능 붙이기

📍 "이제 버튼이 진짜로 동작하게 만들어요. PRD의 핵심 기능을 하나씩 붙이고, 붙일 때마다 직접 눌러 보실 거예요."

**③이면 여기서 `light-login.md`를 읽고, 로그인과 DB부터 붙인 다음 기능으로 넘어가요.** 아래 "② 저장 요령" 대신 light-login.md의 저장 방법을 써요.

**순서**: PRD 핵심 기능 1 → 2 → 3. 기능마다 아래를 반복해요.
1. 무엇을 만들지 한 줄로 말해요.
2. 만들어요.
3. 로컬 링크에서 사용자가 직접 눌러 보게 해요. "추가 버튼 눌러 보시고, 새로고침해도 남아 있는지 봐 주세요."
4. 괜찮으면 커밋해요.

### ② 저장 요령 (Claude용)

- 저장 코드는 `src/lib/storage.ts` 한 곳에 모아요. 키 이름에 이름과 버전을 붙여요 (예: `today-three:v1`).
- 읽기 · 쓰기는 `try/catch`로 감싸요. 시크릿 모드나 저장 공간이 꽉 찬 경우에도 멈추지 않게요.
- Next.js는 서버에서 화면을 먼저 그려서, localStorage는 화면이 뜬 뒤(`useEffect`)에 읽어요. 해당 컴포넌트에는 `"use client"`를 붙여요. 이걸 놓치면 "Hydration failed" 오류가 나요.
- Next.js 16의 검사 규칙은 `useEffect` 안에서 바로 상태를 바꾸면 오류로 잡아요 (`react-hooks/set-state-in-effect`). 저장소를 한 번 읽는 그 줄 위에만 아래 주석을 달아요. `useSyncExternalStore`로 읽으면 주석 없이도 통과해요.
  ```
  // eslint-disable-next-line react-hooks/set-state-in-effect -- 브라우저 저장소는 화면이 뜬 뒤에만 읽을 수 있어요
  ```
- "오늘 날짜" 같은 값을 `useState`의 처음 값으로 바로 넣지 않아요. 빌드할 때 그려 둔 화면에 빌드 날짜가 박혀서 화면이 어긋날 수 있어요. 화면이 뜬 뒤에 정해요.
- **읽을 때는 형식이 틀린 줄만 건너뛰고 나머지는 지켜요.** 한 줄이 깨졌다고 빈 목록을 돌려주면, 다음 저장 때 진짜 데이터를 덮어써서 잃어버려요. 아예 읽을 수 없으면 원래 글자를 `<키>:broken` 같은 다른 키에 옮겨 두고 사용자에게 알려요.
- 같은 검사 함수를 백업 가져오기에도 써요. 링크를 저장하는 소프트웨어면 `http://`, `https://`로 시작하는 주소만 받아요.
- 처음 켰을 때(데이터 0개) 화면을 꼭 만들어요. 빈 화면 대신 "첫 기록을 추가해 보세요" 안내와 버튼을 보여 줘요.

### ② 백업 (추천)

- "내보내기" 버튼: 데이터를 JSON 파일로 내려받아요.
- "가져오기" 버튼: 파일을 골라 불러와요. 형식이 틀리면 "백업 파일이 아니에요" 안내만 띄우고 멈춰요. 덮어쓰기 전에 확인받아요.
- 사용자에게 설명해요. "브라우저 기록을 지우면 데이터도 지워질 수 있어요. 가끔 내보내기 해 두면 안전해요. 다른 기기로 옮길 때도 써요."

### 폰에서 주로 쓴다면

앱 아이콘과 이름을 넣어 두면(`src/app/manifest.ts`, 아이콘 파일) 폰에서 "홈 화면에 추가"했을 때 앱처럼 열려요. 폰에서 주로 쓰는 사람에게는 기본으로 넣어요. ②를 아이폰에서 쓰면 홈 화면에 추가해야 기록이 오래 남아요.

## 6단계 · 보안 점검

📍 "인터넷에 올리기 전에 문단속을 해요. 단순한 소프트웨어여도 꼭 해요."

`security-checklist.md`의 공통 · 링크형 항목(③은 로그인 항목까지)을 돌려요. 결과를 표로 보여 주고, 실패 항목은 고친 뒤 다시 확인해요. `npm run lint`와 `npm run build`가 오류 없이 끝나는지도 확인해요. 여기서 나는 오류는 배포에서도 똑같이 나요.

## 7단계 · 배포

📍 "이제 내 컴퓨터에만 있던 소프트웨어를 인터넷에 올려서, 링크만 있으면 어디서든 열리게 해요. 이걸 배포라고 해요."

1. 사용자가 vercel.com에서 직접 가입해요 (Google, GitHub, 이메일 중 편한 걸로). **Hobby(무료)**를 고르고, 유료 플랜(Pro) 체험이나 카드 등록 화면이 나오면 건너뛰어요. Claude는 가입을 대신하지 않아요.
2. 사용자가 직접 로그인해요. "Claude Code 입력창에 `! npx vercel login`이라고 쳐 주세요. 브라우저 창이 열리면 확인을 누르면 돼요." 메뉴에서 막히면 터미널 앱에서 `<영어-이름>` 폴더로 이동해 실행하게 해요. 윈도우 PowerShell에서 막히면 `npx.cmd vercel login`으로 해요.
3. **③이면** Supabase 주소와 공개용 키를 Vercel에도 알려 줘야 해요. 사용자가 Vercel 대시보드 → 프로젝트 → Settings → Environment Variables에 `.env.local`과 같은 이름으로 두 개를 넣어요. 공개용 키만 넣고 비밀 키는 넣지 않아요. 첫 배포 뒤에 프로젝트가 생기니, 1차 배포 → 변수 넣기 → 다시 배포 순서여도 괜찮아요. 변수를 넣은 뒤에는 **꼭 다시 배포해요.** `NEXT_PUBLIC_`으로 시작하는 값은 빌드할 때 화면 코드에 들어가서, 변수만 넣고 새로고침하면 계속 "연결되지 않았어요"가 보여요.
4. Claude가 `<영어-이름>` 폴더에서 `npx vercel --prod --yes`로 배포해요.
5. 나온 주소(`https://<이름>.vercel.app`)를 열어 확인하고, **폰으로도 열어 보게 해요.** 기록을 추가하고 새로고침해서 남아 있는지 봐요. ③은 폰과 노트북에서 같은 기록이 보이는지 확인해요.
6. `curl -I <주소>`로 보안 헤더가 붙었는지 확인해요.

**배포 뒤에 알려 줄 것**
- ②: "링크를 아는 사람은 누구나 열 수 있어요. 하지만 각자 자기 브라우저 기록만 보여요."
- ③: "링크를 아는 사람은 누구나 가입할 수 있어요. 하지만 각자 자기 기록만 보여요. DB에서 막아 뒀거든요."
- "수정한 다음 '다시 배포해 줘'라고 하시면 같은 주소에 새 버전이 올라가요."
- 주소는 `.vercel.app`을 그대로 써요. 내 도메인은 돈을 내고 사야 해서 이번엔 하지 않아요.

배포에서 막히면 로그인이 풀렸는지(`npx vercel whoami`), 빌드 오류인지 먼저 봐요. 계속 막히면 오늘은 로컬 링크로 확인하고, 배포는 다음에 이어서 해도 된다고 안내해요.

**GitHub로 올리고 싶은 사람**: GitHub 계정이 있으면 비공개(Private) 저장소에 올리고 Vercel과 연결할 수 있어요. 올릴 때마다 자동으로 다시 배포돼요. 원하는 사람에게만 객관식으로 제안해요.

## 설치 없이 여는 버전 (② 변형 · 회사 컴퓨터 등)

0단계에서 "프로그램 설치가 막혀 있어요"가 나왔고, **혼자 이 컴퓨터에서만** 쓴다면 이 방법으로 만들어요. Node.js · Next.js · 배포가 모두 필요 없어요.

- **모양**: `index.html` 파일 하나. 더블클릭하면 브라우저로 열려요. 바탕화면에 바로가기를 두면 앱처럼 쓸 수 있어요.
- **만드는 법**: HTML · CSS · JavaScript를 파일 하나에 다 넣어요. 바깥 인터넷 주소에서 아무것도 불러오지 않아요(글꼴도 기본 글꼴).
- **저장**: 브라우저 저장소(localStorage). ② 저장 요령과 백업(내보내기 · 가져오기)을 그대로 적용해요.
- **알려 줄 것**: "이 파일을 다른 브라우저로 열면 기록이 따로 보여요. 늘 같은 브라우저로 여세요." · "브라우저 기록을 지우면 데이터도 지워질 수 있어요. 가끔 내보내기를 해 두세요."
- **회사 업무 내용**을 담는다면 회사 규정을 한 번 확인하자고 안내해요. 외부로는 아무것도 보내지 않는다고 PRD 안전 칸에 적어요.
- 4단계(화면 먼저) → 5단계(기능)는 똑같이 가고, 6단계 보안 점검은 공통 항목만, 7단계 배포는 건너뛰어요.
