# 보안 점검표

6단계(배포 · 설치 전)에 돌려요. 단순한 소프트웨어여도 꼭 해요. 입문자는 무엇이 위험한지 모르기 때문에, Claude가 하나씩 확인하고 결과를 표로 보여 줘요.

```
| # | 확인한 것 | 결과 | 쉬운 설명 |
|---|---|---|---|
| 1 | 비밀 키가 코드에 없다 | ✅ 통과 | 남이 내 계정으로 돈을 쓸 수 있는 열쇠가 코드에 없어요 |
| 2 | ... | ❌ 실패 → 고쳤어요 | ... |
```

실패 항목은 무엇을 어떻게 고칠지 먼저 말하고 고친 뒤, 다시 확인해서 ✅로 바꿔요. 확인할 수 없는 항목은 "확인 불가"로 솔직하게 적어요. 검색 결과에 걸린 게 진짜 문제인지 아닌지도 쉬운 말로 설명해요. 예: "`js-tokens`는 패키지 이름이라 괜찮아요."

---

## 공통 (모든 모양)

| 확인할 것 | 확인 방법 | 통과 기준 |
|---|---|---|
| 비밀 키 · 비밀번호가 코드에 없다 | `git grep -niE 'api_key\|secret\|service_role\|sb_secret_\|password\|sk-[A-Za-z0-9]{10,}\|-----BEGIN' -- . ':!package-lock.json'` 결과를 직접 읽어요 | 진짜 키나 비밀번호가 없다. 변수 이름만 걸린 건 괜찮아요 |
| `.gitignore`가 맞다 | 파일을 열어 봐요 | 링크형: `.env*`, `node_modules`, `.next`, `.vercel` / 설치형: `.build`, `build` |
| git 기록에 비밀이 없다 | `git log -p`에서 위 단어를 찾아요 | 한 번이라도 커밋된 키가 없다. 있으면 그 키는 새로 발급하라고 안내해요 |
| 민감한 정보를 받지 않는다 | 입력칸을 모두 훑어봐요 | 주민번호, 카드 · 계좌번호를 묻는 칸이 없다. 비밀번호는 ③의 로그인 칸에만 있다 |
| 남의 개인정보를 쌓지 않는다 | 고객 · 환자 · 회원 · 거래처를 다루는지 봐요 | 연락처, 건강 정보 같은 칸이 없고 별명이나 번호로 구분한다. 회사 업무 내용이면 개인 서비스에 저장해도 되는지 사용자에게 한 번 물었다 |
| 실존 인물 정보가 예시에 없다 | 가짜 데이터, 안내 문구를 훑어봐요 | 실제 이름, 전화번호, 이메일이 없다 |
| 계정 작업은 사용자가 했다 | 대화를 돌아봐요 | Vercel · Supabase 가입, 로그인, 설치 승인, 로컬 링크의 테스트 가입을 Claude가 대신하지 않았다 |
| 돈이 나가지 않는다 | 쓴 서비스를 돌아봐요 | 모두 무료 플랜이고, 카드를 등록하지 않았다 |

## 링크형 (② · ③)

| 확인할 것 | 확인 방법 | 통과 기준 |
|---|---|---|
| 위험한 코드가 없다 | `dangerouslySetInnerHTML`, `innerHTML =`, `eval(`, `new Function(`을 찾아요 | 하나도 없다. 사용자가 쓴 글이 코드로 실행될 틈이 없어요 |
| 링크 입력이 안전하다 | 링크를 넣는 기능이 있으면 봐요 | `http://`, `https://`만 링크로 만들고, 새 창 링크에 `rel="noopener noreferrer"`가 있다 |
| 외부 스크립트 · 추적 도구가 없다 | `<script src=`, 분석 도구 코드를 찾아요 | 모르는 곳에서 불러오는 코드가 없다 |
| 사용자 데이터를 밖으로 보내지 않는다 | `fetch(` 사용처, `src/app/api` 폴더를 봐요 | ②는 외부로 보내는 곳이 없다. ③은 Supabase로만 보낸다. 기록 내용을 주소(URL)에 넣지 않는다 |
| 저장 데이터가 조용히 사라지지 않는다 (②) | `src/lib/storage.ts`를 봐요 | 깨진 줄만 건너뛰고, 읽기 실패 때 빈 목록으로 덮어쓰지 않는다 |
| 백업 가져오기가 안전하다 (②) | 가져오기 코드를 봐요 | 형식을 확인하고, 틀리면 안내만 띄운다. 덮어쓰기 전에 확인받는다 |
| 패키지에 알려진 구멍이 없다 | `npm audit --omit=dev` | high, critical이 0개. 있으면 `npm audit fix`(`--force` 없이)를 해 보고, 남으면 사용자에게 설명해요 |
| 검색엔진에 안 뜬다 | `layout.tsx`의 `metadata` | `robots: { index: false, follow: false }`가 있다 |
| 기본 보안 헤더가 있다 | `next.config.ts`의 `headers()` | `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `Permissions-Policy`(카메라 · 마이크 · 위치는 쓰는 것만)가 있다 |
| 문법 검사 · 빌드가 된다 | `npm run lint`, `npm run build` | 둘 다 오류 없이 끝난다 |
| 헤더가 실제로 붙는다 | 배포 전: `npm run build && npx next start -p 3001` 후 `curl -I http://localhost:3001` / 배포 후: `curl -I <주소>` | 위 헤더가 응답에 있다 |

헤더를 설명할 때: "다른 사이트가 내 소프트웨어를 몰래 품어서 보여 주거나, 쓰지 않는 카메라 · 마이크 권한을 요청하지 못하게 막는 설정이에요."

## 가벼운 로그인 (③)

| 확인할 것 | 확인 방법 | 통과 기준 |
|---|---|---|
| 모든 테이블에 잠금(RLS)이 켜져 있다 | `schema.sql`, Supabase 대시보드 Table Editor의 RLS 표시 | 모든 테이블에 `enable row level security`와 select · insert · update · delete 정책이 있다 |
| 다른 계정의 기록이 안 보인다 | `light-login.md` 5번 테스트 | `test_b`로 `test_a`의 기록이 안 보인다 |
| 로그인 없이 물어보면 비어 있다 | `light-login.md` 5번의 `curl` 명령 (`.env.local`을 먼저 불러와요) | `[]` 또는 `permission denied`가 나온다 |
| 관리자 키를 쓰지 않는다 | `service_role`, `secret`, `sb_secret_`을 찾고 `.env.local`을 열어 봐요 | 코드와 `.env.local` 어디에도 없다. 공개용 키 칸에는 `sb_publishable_…` 또는 `anon` 키가 들어 있다 |
| 키가 없어도 빌드가 된다 | `.env.local`을 비운 채 `npm run build` | 멈추지 않고, 화면에 "연결되지 않았어요" 안내가 뜬다 |
| `.env.local`이 올라가지 않는다 | `git status`, `git log --stat` | 커밋된 적이 없다 |
| 비밀번호 규칙이 있다 | Supabase 설정, 가입 화면 | 8자 이상이다 |
| 글자 수 제한이 있다 | `schema.sql`의 `check` | 긴 글로 DB를 채울 수 없다 |
| 테스트 계정을 정리했다 | 사용자에게 확인해요 | 테스트 계정을 지웠거나, 지우는 법을 안내했다 |

로그인을 설명할 때: "링크를 아는 누구나 가입은 할 수 있어요. 하지만 DB에 걸어 둔 잠금 덕분에 각자 자기 기록만 볼 수 있어요. 그 잠금이 진짜로 걸렸는지 방금 직접 확인했어요."

## 설치형 (①)

| 확인할 것 | 확인 방법 | 통과 기준 |
|---|---|---|
| 영구 삭제가 없다 | `removeItem`, `rm -`를 찾아요 | 지우기는 `trashItem`(휴지통)만 쓴다 |
| 되돌릴 수 있다 | 앱에서 직접 해 봐요 | 휴지통으로 보낸 파일, 옮긴 파일, 이름 바꾼 파일을 앱 안에서 되돌릴 수 있다 |
| 덮어쓰지 않는다 | 이름 바꾸기 · 옮기기 코드를 봐요 | 같은 이름이 있으면 뒤에 ` 2`를 붙인다 |
| 건드리지 않는 곳을 지킨다 | 후보를 고르는 코드를 봐요 | `~/Library`, 시스템 폴더, `.app`, 동기화 폴더(동의한 iCloud 바탕화면 제외), 최근 파일, 다운로드 중인 파일이 빠진다 |
| 사용자가 고른 것만 움직인다 | 동작 코드를 봐요 | 자동 삭제 · 자동 이동이 없다. 묶음 처리는 개수를 확인받은 뒤에만 한다 |
| 인터넷을 쓰지 않는다 | `URLSession`, `http`를 찾아요 | 네트워크 코드가 없다 |
| 관리자 권한을 쓰지 않는다 | `sudo`, 권한 상승 코드를 찾아요 | 없다 |
